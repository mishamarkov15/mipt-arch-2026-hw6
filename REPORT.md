# Отчет по рефакторингу

## Найденные и исправленные проблемы

### Нарушение Interface Segregation Principle

В исходной версии абстрактный класс `CurrencyConverter` требовал реализовать методы `convert_usd_to_eur`, `convert_usd_to_gbp`, `convert_usd_to_rub` и `convert_usd_to_cny` во всех наследниках. Из-за этого каждый конкретный конвертер был вынужден содержать методы, которые к нему не относятся, и печатать сообщения вида `This is not USD to ... converter`.

Исправление: вместо широкого интерфейса добавлен единый метод `convert(amount, target_currency)`. Старые классы `UsdRubConverter`, `UsdEurConverter`, `UsdGbpConverter` и `UsdCnyConverter` оставлены как небольшие адаптеры для совместимости.

### Нарушение DRY

Получение курсов валют было продублировано в нескольких файлах. В разных классах по-разному настраивались таймауты, повторные попытки, логирование и обработка ошибок.

Исправление: общий код получения курсов вынесен в `RequestsExchangeRateProvider`, а кэширование вынесено в `CachedExchangeRateProvider`. Теперь правила обращения к API и работы с кэшем описаны в одном месте.

### Нарушение Single Responsibility Principle

Классы конвертеров одновременно отвечали за загрузку данных из сети, кэширование, обработку ошибок и сам расчет суммы.

Исправление: обязанности разделены. Провайдеры отвечают за получение курсов, `CurrencyConverter` отвечает только за конвертацию, а `main.py` отвечает только за ввод и вывод.

### Нарушение Open/Closed Principle

Для добавления новой валюты раньше нужно было создавать новый класс, добавлять новый метод в абстрактный класс и реализовывать заглушки во всех существующих наследниках.

Исправление: новая валюта теперь не требует изменения интерфейса или создания отдельного класса. Достаточно передать код валюты в метод `convert`.

### Низкая устойчивость к ошибкам

Один из конвертеров не проверял HTTP-ошибки и не использовал таймаут. Некоторые классы возвращали `None` при ошибке загрузки курсов, после чего приложение могло упасть с неочевидной ошибкой при обращении к `self.rates[...]`.

Исправление: ошибки получения курсов приводятся к явному исключению `CurrencyConversionError`, запросы выполняются с таймаутом и повторными попытками, а пользовательский ввод проверяется перед конвертацией.

### Низкая читаемость и лишние зависимости

В `main.py` был неиспользуемый импорт `asyncio` и wildcard import `from converters import *`. Это усложняло понимание зависимостей модуля.

Исправление: оставлены только явные импорты нужных классов. Логика вывода результатов сделана циклом по списку поддерживаемых валют.

### Служебные файлы в репозитории

В репозиторий попали файлы `__pycache__` и `.pyc`, которые не относятся к исходному коду и затрудняют чтение изменений.

Исправление: в `.gitignore` добавлены `__pycache__/`, `*.pyc` и файл кэша `exchange_rates.json`.

## Итог

После рефакторинга код стал проще расширять: можно добавлять новые валюты без создания новых классов и без изменения абстрактного интерфейса. Повторяющаяся логика загрузки курсов находится в одном месте, обработка ошибок стала более предсказуемой, а консольный интерфейс отделен от бизнес-логики.
